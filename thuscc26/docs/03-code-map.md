# 读代码时从哪里入手

你不需要先逐行掌握整个HPL。先能将“目标、配置、启动、结果”串起来，再按问题查看相应实现。比赛允许优化配置，不允许改HPL源码。

## 文件分工

| 文件/目录 | 回答的问题 | 何时查看 |
|---|---|---|
| `HPL.dat` | 算多大的问题、如何分块、进程如何组成网格？ | 调参数或解释结果前 |
| `Make.Linux_Intel.in` | 用哪个编译器、MPI、BLAS和编译选项？ | 构建或更换库前 |
| `slurm/run.slurm` | 申请多少节点/核、准备什么环境、怎样启动？ | 提交前 |
| `testing/ptest/HPL_pddriver.c` | 测试主流程怎样读取配置、组织测试？ | 理解程序入口和测试循环 |
| `testing/ptest/HPL_pdinfo.c` | 输入参数怎样解析和检查？ | 解释参数或非法输入 |
| `testing/ptest/HPL_pdtest.c` | 怎样计时、计算GFlops和检查残差？ | 读日志、理解正确性和评分 |
| `src/pgesv/` | 分布式线性方程求解怎样组织？ | 理解整体算法 |
| `src/pfact/`、`src/panel/` | 面板分解和管理做什么？ | 理解NB、递归分解等参数 |
| `src/blas/HPL_dgemm.c` | 怎样调用矩阵乘法？ | 理解数学库为何影响性能 |
| `src/comm/`、`src/grid/` | 进程网格和通信怎样工作？ | 理解P/Q、广播和通信开销 |
| `TUNING` | 各输入项的含义、可选值和调优建议？ | 每次不确定参数含义时 |

上表路径是**HPL源码根目录的相对路径**。仓库顶层保留上游版本供浏览；实际比赛构建路径是 `.work/src/hpl-2.3/`。查看精确构建实现时以发布包为准。

## 读懂 HPL.dat 的最小能力

该配置依赖行的顺序；初学者每次只改一个明确字段，修改后对照原文件和运行日志检查。

| 行 | 当前值 | 含义 |
|---|---|---|
| 1–2 | 描述文字 | 标题；本公开副本第二行改为通用说明，不影响数值配置 |
| 3–4 | HPL.out / 6 | 输出名与设备号；6表示标准输出，因此由Slurm日志接收 |
| 5–6 | 1 / 120000 | 一个问题规模，N=120000 |
| 7–8 | 1 / 384 | 一个NB候选，NB=384 |
| 9 | 0 | 按行映射进程 |
| 10–12 | 1 / 8 / 14 | 一个网格，P8×Q14=112进程 |
| 13 | 16.0 | 残差阈值；保持正确性标准 |
| 14–31 | 其余算法参数 | 逐项查看TUNING，不凭数字猜含义 |

例如从384改为336时，仅改第8行。提交后应在日志参数表看到 `NB : 336`，并再次检查 `PASSED`。

## 读懂运行脚本的最小能力

```text
#SBATCH ...                   Slurm读取的资源申请和日志路径
cd "$SLURM_SUBMIT_DIR"         进入本次提交目录，读取该目录输入
module load ...               选择Intel编译器/MPI/MKL环境
export ...                    设置后续子进程继承的环境变量
mpirun -np ... ./xhpl         启动多个HPL进程
```

“环境”包括软件、路径、库和配置等整体条件；“环境变量”是进程可继承的键值设置，是准备环境的一种机制。MPI是进程通信标准，Intel MPI等库实现它，`mpirun`负责启动遵循该通信模型的并行程序。`xhpl`是编译后的二进制，用编辑器打开它不能像C源码一样阅读。

## 读日志的顺序

1. 起止时间、作业号、节点、进程数：确认读的是哪次运行。
2. HPL版本和参数表：确认实际使用的配置。
3. 结果行 `N NB P Q Time Gflops`：读取问题和性能。
4. 残差 `<16`、`PASSED`、失败/跳过数量：确认计算有效。
5. 退出码与错误输出：排查程序、库或通信异常。

`4.0722e+03 GFlop/s`等于4072.2 GFlop/s，即4.0722 TFlop/s。它衡量标准浮点工作量的完成速率，不是任意CPU指令数；数值正确且条件可比时越大越好。
